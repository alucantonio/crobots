# hal9025 — Strategy Analysis

**Tournament:** Crobots 2025 (40th Anniversary), "Macro" pool — **rank 9 of 24**, total 48.60 % won
(F2F **71.00 %** — 6th in F2F, 3v3 41.77 %, 4v4 33.03 %)
**Author:** Maurizio Camangi
**Class:** Midi (Classic) — **v13.04** (from HAL9000 v12, 2020)
**Local file:** `robots/2025/hal9025.r` (285 lines, ~100 header)

## Core idea

HAL9000 is a **two-corner duelist with an explicit attack/defence state machine** and a
"pod" hover-and-fire routine. The header states the v13 changes over v12:

> *"HAL9000 v13 is an improved (!?) version of HAL9000 v12 (2020).
> Differences: - Slightly more aggressive - Switch side only if hit."*

It is the most *stateful* of the eight: a per-corner `attack` bit, a damage
delta-tolerant `pod()`, and a "go crazy" terminal loop for when the field is empty.
It shares its fire routine **word-for-word with kerberos** (the only difference: HAL
puts the look-ahead line inside `fire()`, where kerberos has it in `main()`; see
[kerberos.md](kerberos.md)) — both descend from Tobey (2007), so the two are
siblings, not rivals.

## The anchor corner & the `clock` side-bit

The robot anchors on its **spawn corner** (the `(x,y)` target set once, at 20/980 from
the walls) and works it with a **side bit** `clock` (0 or 1) that selects *which side —
arc and direction bias — it is working right now*:

```c
    degree(x=20+960*(posx=loc_x()>499), y=20+960*(posy=loc_y()>499));
    corner(deg1=90*((posy<<1)|(posx^posy)));
    while (dave=(t=1)<<clock)
```

- `degree(x,y)` computes the heading to (x,y) via `atan` + an 180° sign bit —
  note it *writes `dir`* as a side effect.
- `deg1` is the near-corner heading (quadrant pick, same formula as the others).
- `while(dave=(t=1)<<clock` is the **infinite loop written as an assignment**:
  `dave` is always 1 or 2 (never 0), so the condition is always true, and `dave`
  doubles as the *per-side attack bit* (bit 0 = side 0, bit 1 = side 1).
  The variable is named `dave` — *"Dave, I am afraid I cannot do that…"* — a
  2001: A Space Odyssey joke on a robot that refuses to be easily killed.

Each iteration checks whether the **other** corner is occupied:

```c
    if (radar(deg1+70*clock))
    {
        /* if opposite corner is occupied ... */
        d=damage(dir=deg1 + (30<<clock));
        if (attack&dave)
        {
            /* attack mode */
            if (damage(pod(5)/* pod(1) */)>d) { attack&=~dave; clock^=1; }
        }
        else
        {
            /* defensive mode */
            while((speed(fire())<100) || ((++t<3) && (damage()==d))) ;
            if(damage()>d) { pod(1); clock^=1; }
            else attack|=dave;
        }
    }
    else
    {
        /* ... otherwise go crazy */
        dir=deg1 + 15 + (60*clock);
        pod(5)/* pod(3) */;
        attack|=dave;
    }
    corner(fire2());
```

The logic per corner:

1. **`radar(corner)`** — is there an opponent on this corner's arc?
2. **If yes → engage it.**
   - **Attack mode** (`attack & dave` set): run `pod(5)`; if it came back *more*
     damaged than before (`> d`), clear this corner's attack bit and **switch corner**
     (`clock^=1`).
   - **Defensive mode** (bit not set): wait (firing) until either it lands a shot
     (`speed(fire())>=100` — i.e. a hit) **or** 3 tries pass *without* taking damage.
     - If it *is* hit (`damage()>d`): `pod(1)` (flee-tolerant) and switch corner.
     - If it wins the exchange: **escalate** — set the attack bit for next time
       (`attack|=dave`).
   - This is the "switch side **only** if hit" rule: the bit is cleared *and* the side
     flipped only on taking damage; winning keeps it committed.
3. **If no → "go crazy"**: pick a heading between the two corners
   (`deg1+15+60*clock`), run `pod(5)`, and arm the attack bit — a committed offensive
   posture when the field looks open.
4. **`corner(fire2())`** (with `fire2()` passed as an ignored argument — fire once more)
   always re-runs the approach to the anchor corner at the end, so the robot
   perpetually *returns to its corner* while the above sets the tempo.

## `pod(delta)` — hover, fire, and bail on damage

The most compact and clever bit in the pool. It is a *single* `while` whose exit
condition is a function of both its own motion and whether it got hit:

```c
pod(delta)
int delta;
{
  int d;
  d=damage()+delta;
  while(dista(x,y) < (123450-4925*(damage(fire())>d))) ;
}
```

Reading it:

- `d = damage()+delta` — set a threshold that allows up to `delta` points of new damage.
- Loop while the *squared* distance to the corner target `(x,y)` is **less than**
  `123450 − 4925·(was-i-just-hit)`.
  - `123450` ≈ (351 m)² — the outer edge of the **hover band**: the pod keeps firing
    while it is within roughly 350 m of the corner target.
  - `damage(fire())>d` is `1` *iff* this call to `fire()` increased damage beyond the
    `delta` tolerance; then the bound drops to `123450−4925` ≈ (344 m)², so a pod
    drifting outward **exits sooner** — the pod bails early when hit.
  - While safe, `fire()` keeps being called (it's inside the condition), so the pod
    **fires continuously while it hovers**, and stops the instant it is hit beyond
    tolerance.
- `delta` is the aggression dial: `pod(5)` (attack / go-crazy) tolerates 5 damage
  points; `pod(1)` (defensive) bails after just 1. The commented `/* pod(1) */` /
  `/* pod(3) */` are the author's tuning history.

This encodes "hover at the corner, keep firing, and retreat the moment I'm badly hit"
in three lines — the statefulness that `dave`/`attack`/`clock` manage around it.

## `corner()` — approach, settle, and count enemies

```c
corner() /* Get closer to corner */
{
    int dist;
    drive(degree(x, y), 100);
    while( (dist = dista(x, y)) > 8100 )
    {
        if(dist < 25600) ;
        else fire(dir);
    }
    fire2(0);
    while(speed()>59);
    if ( ++timer%12 == 1 )
    {
        if ((
              (scan(deg1,    10)!=0)
             +(scan(deg1+20, 10)!=0)
             +(scan(deg1+40, 10)!=0)
             +(scan(deg1+60, 10)!=0)
             +(scan(deg1+80, 10)!=0)
             +(scan(deg1+100,10)!=0)
             ) < 2 )
        {
            while(1)
            {
                if (((posx=loc_x())%880)<120) dir=180*(posx>500);
                else if (((posy=loc_y())%880)<120) dir=90+180*(posy>500);
                else if (range>610) dir=ang+25;
                else if (range<180) dir=ang+195;
                else dir=ang+180*(clock^=1);

                fire2(100);
                fire2(100);
                fire2(100);
            }
        }
    }
}
```

- Drives to the corner, but **only fires while far** (`dist ≥ 25600` ≈ 160 m); once in
  the `>8100` (≈ 90 m) inner zone it coasts in quietly — approaching without giving away
  its firing rhythm.
- `while(speed()>59)` — **waits out the coast** before thinking (same habit as
  [ironman_25](ironman_25.md)'s `Stop`, opposite of jedi15's commented-out coast wait).
- Every 12th arrival it runs a **6-cone enemy count** on the corner arc; if **fewer
  than 2** are found, it enters the **terminal "go crazy" loop** — a `while(1)` that
  dances between wall-hugging, orbiting (`ang+25`), backing off (`ang+195`), and
  zig-zagging (`ang+180·clock`, flipping `clock`), firing three times per tick. Like
  Gerty6's terminal dance, this is a **committed terminal state** with no exit — HAL has
  decided the field is empty enough to go full offensive and stays there.
- `dista()` is squared distance — the comment *"avoid sqrt()"* — so the `8100/25600/
  123450` constants are **squared metres**, not metres.

## The fire routines

`fire()` + `find()` + `search()` are **identical to kerberos'** (the Tobey lineage) —
the `/14384` / `/3796−230` / `*(880+range)/482` / `*230/(Δ−acos)` lead, the ±13/12/11
`find`, and the 5-step +recursive `search`. See [kerberos.md](kerberos.md) for the full
breakdown. The one difference: HAL calls `fire()` under the `speed()<100` gate and the
`pod`/defensive waits, so it fires *less often but in more deliberate bursts* than
kerberos.

`fire2(v)` is the **shared doubling shot** core (`(ang<<1)-oang` / `(scan<<1)-range`)
with the ±8/±5/±2 refinement and ±20/40/60/80 fallback — the same model as
[wall-e_vii](wall-e_vii.md)'s `fire2` and [gerty6](gerty6.md)'s `fire2`:

```c
        return(cannon((ang<<1)-oang,(scan(ang,10)<<1)-range));
```

`radar(sc)` is a minimal threat probe — two consecutive cones, and if either sees
someone it sets `ang = sc` (the starting bearing for the next fire) and returns 1:

```c
if ( scan(sc,     10) ) ;
else if ( scan(sc+=20, 10) ) ;
else return 0;
ang = sc;
return 1;
```

In the main loop it is called as `radar(deg1+70*clock)` — the side-0 arc when
`clock=0`, a rotated arc when `clock=1`.

## The state bits at a glance

| variable | meaning |
| --- | --- |
| `clock` | **which side** to work (arc/direction bias, 0 or 1); flipped *only* on taking damage |
| `dave`  | `1<<clock` → the **per-side** slot of the `attack` mask (1 or 2) |
| `attack`| bitmask of which corners are currently in **attack mode** |
| `t`     | per-exchange try counter (defensive: bail after 3 without a hit) |
| `timer` | corner-arrival counter; `timer%12==1` triggers the enemy count |

This is the cleanest explicit **per-side policy** in the pool: *each side can
independently be attacking or playing safe*, and a hit is the only thing that demotes a
side or flips you to the other one. That matches its tournament signature — strong
F2F (71 %), weaker in 3v3/4v4 (41.8 % / 33.0 %) — it is built to run a *pair* of
corners against a single opponent.

## Notable traits / quirks

- **Two terminal doors** (the `while(1)` in `corner()` when the field looks empty, and
  the committed `pod`-driven loops) — like Gerty6, HAL can enter states it does not
  return from; the difference is HAL's terminals are *offensive* rather than
  *evasive*.
- **`speed(fire())` and `damage(fire())`** — side-effecting `fire()` calls embedded in
  loop conditions are a Camangi/Olga S idiom here (fire, and *return a value I then
  inspect*). Read them as "fire(), and tell me if it hit".
- **Square-distance discipline** (`dista`, all `> N` constants squared) to avoid
  `sqrt` — a deliberate integer-only budget in a Midi-class robot.
- **Tobey fire core** (shared with kerberos) + **doubling `fire2`** (shared with
  wall-e_vii / gerty6 / thor_25) = HAL is essentially a *fire-router* over two well-trodden
  routines, with its own state machine on top.
- The `/* pod(1) */` / `/* pod(3) */` comments show live A/B tuning of the aggression
  delta between releases.
